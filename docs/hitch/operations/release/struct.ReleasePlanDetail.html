Expand description

The release-specific payload a plan carries.

Fields§

§environment: String§target: String§released: Vec<PlannedBranch>

Each promoted branch, pinned to the SHA the composition consumed, in declaration order. A release folds branches in one at a time and the order decides the merge order, so this list is never sorted.

§squash: bool§result_sha: String

The composed target tip. Already in the object database — the module header explains why that is not an implementation detail.

§anchor_ref: Option<String>

The ref anchoring the composed commit between planning and publishing, or None for a preview. See discard_release_plan.

§target_sha_before: String

The refs/heads/<target> value the publish’s CAS will require.

§remote_target_sha_before: Option<String>

The remote target tip observed before composing, so the eventual push is reported against what was observed rather than against whatever the remote has become by the time the release finishes.

§tag_name: String

The base tag name. The executor may land a disambiguated variant of it — create_release_tag handles a same-name collision from a crash-then-immediate-retry — and the receipt records the name that actually exists. The plan says what it intends; the receipt says what is there.
