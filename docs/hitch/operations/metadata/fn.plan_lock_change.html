The one implementation behind plan_lock and plan_unlock.

A lock takes no ConfirmationRequirement. A lock is one keystroke, and §10.2 of the spec is explicit that a prompt is not implied by showing a plan: the plan is still shown, which is decide_gate’s Proceed arm, not a new behaviour. A prompt here would be a change to hitch lock dressed up as a consequence of introducing plans.
